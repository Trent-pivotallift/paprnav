## Required relational and search result

The approved persistence must keep manufacturer and model in separate typed
fields joined by keys. It must not store values such as `"Textron 172I"` or
`"Piper PA-28-181"` as the authoritative product identity.

Conceptually, this packet requires five manufacturer/scope rows and 182 linked
model rows:

Human-review acceptance includes these search expectations:

- the primary workflow resolves aircraft ID to its previously reviewed
  canonical model identity ID, then uses a direct indexed AD-model mapping;
  manufacturer and text-search joins are not required on this hot path;
- make `Textron Aviation Inc.` returns its 130 linked models;
- model `172I` returns the Textron manufacturer relationship;
- make `Piper Aircraft, Inc.` plus model `PA-28-181` returns that exact scope;
- model-only results always display their associated manufacturer; and
- a model linked to the wrong manufacturer or a combined manufacturer/model
  authoritative value is rejected, not normalized silently.

Human domain review accepted this relational separation and aircraft-ID lookup
path on 2026-08-29. Database implementation and performance verification remain
future implementation-gate work.

## Applicability semantics

One shared rule: an airframe model must occur in Table 1 **and** the airplane
must have the complete GFC 500/GSA 28/STC/master-drawing-list configuration in
`ev-applicability`. The shared configuration is one condition definition, not
copied for each manufacturer or model.

- The 182 manufacturer/model designations are captured in the paired-review
  inventory above and remain bound to `ev-model-table-a` and
  `ev-model-table-b`. The inventory, not a flattened display label or the V3
  draft, is the reviewed model-level applicability input.
- Serial number is **not an applicability criterion**. Paragraph (c) supplies
  the complete applicability rule using model and installed configuration and
  states no serial-number predicate. Do not create an `ev-serial` fragment or
  an unknown serial restriction.

## Obligations, timing, and branches

1. `req-software-update` (`ev-compliance`, `ev-update`): one-time software update; calendar threshold 12 months, anchored to effective date. Note 1 supplies a permitted method/reference, not a second obligation (`ev-update-method`).
2. `req-installation-prohibition` (`ev-prohibition`): from the effective date, prohibit installation of the enumerated-or-earlier software versions. This applies to any airplane, not only the Table 1 population.

Garmin SB 22123 Rev A is identified but not retained. The rule expressly says
it is not incorporated by reference (`ev-ibr-none`), so its unseen content may
not supply additional structured facts.
