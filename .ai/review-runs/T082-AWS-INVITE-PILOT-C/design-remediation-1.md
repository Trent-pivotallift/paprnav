# Package C design remediation 1

## T082-C-001 — fixed pending independent verification

Privileged migration/bootstrap no longer reuses the backend image. A dedicated
digest-pinned image contains only Package A's unchanged sealed migration
context, a separately manifested minimal direct-SQL/AWS bootstrap program, and
hash-pinned dependencies. Its fixed entry point, read-only filesystem, file and
module inventory, mount policy, and import-root negatives cover the entire
credential-bearing execution path.

## T082-C-002 — fixed pending independent verification

“Empty deployment” is resolved as a permanently unused bootstrap control plus
zero user, organization, and membership rows—not merely the absence of an
active administrator. An admin-owned, app-inaccessible control row is inserted
in the same advisory-lock-serialized transaction as user, organization,
membership, and audit event. Revocation cannot reopen it. Concurrent distinct
identities, populated state, revoked prior admins, and failure after each write
are mandatory tests.

## T082-C-003 — fixed pending independent verification

The current bootstrap user remains assume-only. Package E requires an explicit
operator-admin updater principal, a fresh caller-identity check, and proof that
it may version/set only the existing `paprnav-terraform-deploy` managed policy.
No such authority is inferred from the current role.

The reviewed policy generator consumes the operator-supplied hosted-zone ID
and emits this least-privilege matrix:

| Principal | Actions | Resource/condition boundary |
| --- | --- | --- |
| operator-admin prerequisite | `iam:CreatePolicyVersion`, `iam:SetDefaultPolicyVersion`, required read/list | exact `arn:aws:iam::527257972989:policy/paprnav-terraform-deploy`; identity recorded before use |
| Terraform deploy role | ACM request/read/tag/delete required by the graph | `us-east-1`, account certificate resources; request/resource `Project=paprnav` where supported |
| Terraform deploy role | WAFv2 create/read/update/tag/associate operations required by the graph | regional paprnav-prefixed web ACL/rule resources in account `527257972989`; create/list wildcards only where AWS has no resource-level form |
| Terraform deploy role | Route53 list/get and record change | list/get on required wildcard; mutation on exact supplied `arn:aws:route53:::hostedzone/<id>` |
| Terraform deploy role | `iam:CreateServiceLinkedRole` | exact RDS/ECS/ELB service-linked-role ARNs plus matching `iam:AWSServiceName`; no delete/edit grant |
| Terraform deploy role | application/invitation secret lifecycle except value read/write | `arn:aws:secretsmanager:us-east-1:527257972989:secret:/paprnav/pilot/*` |
| Terraform deploy role | RDS-managed secret prerequisite: `CreateSecret`, `TagResource`; `kms:DescribeKey` | Secrets Manager name/ARN `rds!db-*` in account/region; exact resolved `aws/secretsmanager` KMS key; no `GetSecretValue` |
| API execution role | `GetSecretValue`, `DescribeSecret` | exact app-database and invite secret ARNs |
| worker execution role | `GetSecretValue`, `DescribeSecret` | exact app-database secret ARN |
| frontend execution/task roles | none | no secret resource |
| migration/reference task role | `GetSecretValue`, `DescribeSecret` | exact RDS-managed admin secret ARN |
| runtime-role task role | previous admin-secret read plus `PutSecretValue`, `DescribeSecret` | exact admin secret read and exact app-database secret write |
| first-admin task role | `GetSecretValue`, `DescribeSecret` | exact RDS-managed admin and one-use first-admin secret ARNs |

AWS documents that RDS-managed master passwords require the caller to have
`secretsmanager:CreateSecret`, `secretsmanager:TagResource`, and
`kms:DescribeKey`; Secrets Manager supports the `secretsmanager:Name` condition
for `CreateSecret`. These are design inputs to the generated policy and IAM
simulator/Access Analyzer checks, not cloud changes.

## T082-C-004 — fixed pending independent verification

Runtime grants are post-migration and exact-manifest driven. The admin owns all
public/control objects; `paprnav_app` owns none. No default privilege is granted.
The allowlist excludes `alembic_version` and the entire `pilot_control` schema,
and a mismatch blocks publication. With services fixed at zero, a password/
secret partial failure is recovered by rerunning the phase to set and publish a
new value. The task binds the successful `PutSecretValue` response VersionId
to `AWSCURRENT` using `DescribeSecret`, then verifies a new database connection
with the same in-memory generated bytes. This proves publication without
granting `GetSecretValue`; any boundary failure is recovered by a new
zero-service run.

## T082-C-005 — fixed pending independent verification

For an ALB, WAF body inspection is fixed at 8 KiB. The design counts the managed
`SizeRestrictions_BODY` result, adds a custom oversize block for every route
except the exact authenticated multipart upload shape, and retains all other
managed common rules plus independent auth rate limits. The application stream
continues to enforce content type and 100 MiB. A local policy oracle and
representative multipart test precede deployed Package E proof.

References:

- https://docs.aws.amazon.com/waf/latest/developerguide/waf-oversize-request-components.html
- https://docs.aws.amazon.com/waf/latest/developerguide/waf-using-managed-rule-groups.html
