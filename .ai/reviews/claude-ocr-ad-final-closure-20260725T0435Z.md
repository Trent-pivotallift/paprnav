# Findings

## Confirmed Issues (ordered by severity)

### 1. [P2 — Correctness regression, fails safe] Bounded-gap negation regex introduces a new false-negative failure mode: unrelated `not`/`cannot`/`never` clauses in the same comma-separated line flip a genuinely-complied AD to `not_complied`/`not_inspected`, and this bleeds across multiple AD citations sharing one segment

`backend/app/services/maintenance_extraction.py:19-35` (`NEGATED_COMPLIANCE_PATTERN`, `NEGATED_INSPECTION_PATTERN`).

This is the fix that resolves the prior review's finding #1. It now correctly widens the negation guard to a bounded, sentence-scoped window (`[^.;\n]{0,48}`), which correctly catches all the modal-verb phrasings the closure report flagged ("will not be complied with," "cannot be complied with," "is not going to be complied with," and the inspected equivalents) — verified directly and via the new `test_negated_ad_actions_never_become_positive_compliance` (`backend/tests/test_maintenance_extraction.py:55-72`).

However, the window is bounded only by `.`/`;`/newline, not by comma, and `ad_disposition()` is invoked once per whole segment (`maintenance_extraction.py:101`) rather than scoped to the specific AD citation. This produces two new false-negative behaviors, verified directly against `ad_disposition()`/`extract_structured_maintenance_data()`:

- An unrelated negation clause before "complied"/"inspected" in the same comma-joined line flips a real compliance claim to negative:
  - `"Squawk not corrected, AD 2012-01-02 complied with per SB 123"` → `not_complied`
  - `"Part was not available locally, AD 2012-01-02 complied with using substitute part"` → `not_complied`
  - `"Previous owner did not perform annual, AD 2012-01-02 inspected and found airworthy"` → `not_inspected`
- When two distinct AD numbers are cited in one segment, a genuine negation for one AD bleeds onto the disposition of the *other*, unrelated, genuinely-complied AD, because `ad_disposition(segment)` returns a single value applied to every reference found in that segment:
  - `"AD 2011-01-01 was not complied with, AD 2012-01-02 complied with by SB 123"` → **both** references report `not_complied`.

Impact: this degrades matcher precision/recall — a genuinely satisfied AD now routes to `needs_adjudication` (via `explicit_compliance_claim_missing` in `ad_matching.py:151-155`) instead of `candidate_satisfied`, generating unnecessary HITL review load. This is a correctness regression relative to pre-fix behavior (the old immediate-adjacency regex would not have false-triggered on these comma-separated, unrelated clauses), but it **fails safe**: I confirmed the ordering in `ad_disposition()` (not_applicable → negated_compliance → negated_inspection → positive) means a mixed positive/negative segment always resolves toward the conservative disposition, never masking a true non-compliance as satisfied (see Verification Notes). No test exercises multi-clause or multi-AD-per-segment lines, which is a realistic OCR/logbook shape (consolidated "AD status" line entries citing several ADs). Not P1 because it cannot produce a false `candidate_satisfied`.

**Action:** scope negation detection to text local to each specific AD citation (e.g., search only within a window/clause anchored to the citation's own sentence, split on commas or use the citation's match span as the anchor) rather than applying one segment-wide disposition to every AD reference in that segment. Add regression tests for multi-AD-per-line entries and comma-joined unrelated negations.

### 2. [Residual/reopened-adjacent risk, not a regression] The 48-character bounded gap is a hard cutoff, not clause-aware, so sufficiently verbose negation phrasing still reproduces the exact original false-positive-compliance defect

`maintenance_extraction.py:19-35`.

This is not a new regression (the pre-fix regex failed for *any* intervening word, so the fix is a strict improvement), but it does not fully close the underlying defect class from the prior review — it only raises the threshold. Verified: `"AD 2012-01-02 will not be at this time due to an extended parts backorder situation from the overseas supplier complied with"` (85 characters between "not" and "complied") → resolves to `"complied"` (should be `not_complied`). This phrasing is contrived, but the mechanism (an arbitrary character-count cutoff standing in for clause/sentence boundary detection) means the original safety failure mode is narrowed rather than eliminated. Given `.ai/AD_MATCHING_RULES.md`'s stated invariant ("Negated statements ... are never positive compliance evidence"), this is worth tracking as a known limitation rather than treating the fix as a complete guarantee.

**Action:** track as a documented limitation; consider a proper clause-scoped/dependency-aware negation check (or shorter phrase-anchored patterns per compliance verb) if real-world logbook text turns out to contain such long negation-to-verb distances.

## Positive/Notable Closures (confirmed correct)

- **Finding #1 (modal/bounded-gap negations → false positive compliance/inspection):** Resolved for every phrasing explicitly called out in the prior closure report. `will not be complied with`, `cannot be complied with`, `is not going to be complied with`, `will not be inspected`, `cannot be inspected` (and the previously-passing literal forms) all now correctly resolve to `not_complied`/`not_inspected`. Covered by a dedicated new test (`test_maintenance_extraction.py:55-72`) exercising all ten phrasings from the prior review plus the originally-passing cases.
- **Finding #2 (stale matcher results hidden with no signal):** Resolved correctly and non-ambiguously. `list_aircraft_matches` (`backend/app/api/routes/ads.py:95-160`) now computes `matcherStatus` (`current` / `pending_recomputation` / `not_run`) by cross-referencing the current-version match rows against the latest `ad_matching_completed` product event's recorded `algorithm_version`, plus a stale-row existence check, and returns `reprocessingRequired`/`algorithmName`/`algorithmVersion` alongside the (still current-version-only) `matches` list. `ADMatchResultListResponse` (`backend/app/schemas/ads.py:152-157`) carries these new fields, and the frontend type (`frontend/paprnav-frontend/src/lib/api.ts:426-431`) matches exactly, including the literal status union. The end-to-end scenario (aircraft matched under `0.3.0`, then rows/completion-event downgraded to `0.2.0`, then re-queried) is directly tested and asserts `matches == []`, `matcherStatus == "pending_recomputation"`, `reprocessingRequired is True` (`backend/tests/test_ad_matching.py:196-232`), and the "genuinely current, empty is fine" path is implicitly covered by the initial `matcherStatus == "current"` assertion (`test_ad_matching.py:159-161`) while match rows exist. This closes the "ambiguous empty result" gap as instructed — an empty list from a stale-only aircraft is now distinguishable from a genuinely-processed empty list.

# Brief Summary

Both findings from the preceding closure report are genuinely resolved for the specific cases they described: modal-verb/auxiliary negations ("will not be complied with," "cannot be inspected," etc.) now correctly classify as negative disposition and are covered by a dedicated regression test, and the match-list API now exposes an explicit `matcherStatus`/`pending_recomputation`/`reprocessingRequired` signal (backend, schema, and frontend type all consistent) so a stale-only aircraft's empty result is no longer indistinguishable from a genuinely-processed empty result. No P1 safety regression was found — the negation fix's broadened bounded-gap approach cannot produce a new false `candidate_satisfied`, because I traced every consumer of the disposition value. However, the same broadening does introduce a real P2 correctness regression: unrelated negation words elsewhere in a comma-joined logbook line (or a second, genuinely negative AD citation sharing the same line) can now flip a truly-complied AD's disposition to negative, generating unnecessary manual adjudication and reducing matcher precision, and this multi-AD-per-line / multi-clause shape has no test coverage. A separate, non-regression residual risk is that the fix's fixed 48-character cutoff — rather than true clause-boundary detection — means sufficiently verbose negation phrasing can still reproduce the original false-positive-compliance defect, just at a longer distance.
