# Code Review: paprnav AWS pilot + AD/OCR changes

## 1. Findings

### Confirmed issues

**F1 — Synchronous Textract path cannot process the primary input (multi-page / large PDFs). [High for pilot, currently gated behind non-default flag]**
`backend/app/services/ocr_provider.py:215` calls `client.detect_document_text(...)`, and `_document_reference` (`ocr_provider.py:226-233`) either passes an S3 object or reads the **entire file into memory as `Bytes`** for the local backend. Synchronous `DetectDocumentText` does not support multi-page PDFs and is limited to ~10 MB, but:
- `ALLOWED_CONTENT_TYPES` accepts `application/pdf` (`uploads.py:25-29`), and maintenance logs are the core use case.
- `PAPRNAV_MAX_UPLOAD_SIZE_BYTES` defaults to 100 MB (`config.py:58`), far above the sync limit, and the local path loads the whole file into RAM (`path.read_bytes()`).

Your own docs already flag this (`.ai/PROVIDER_REFERENCES.md:67-81`, `.ai/AWS_DEPLOYMENT_STATUS.md:104,157`), but there is no code guard. If anyone sets `PAPRNAV_OCR_PROVIDER=textract` for the pilot, PDF ingestion will fail at runtime with `UnsupportedDocumentException`/size errors. Recommend either implementing async `StartDocumentTextDetection` before enabling, or explicitly rejecting PDFs / >sync-limit files when provider is Textract. Default remains `deterministic`, so this is not breaking CI today.

**F2 — AWS Budget is created with no notification subscribers by default. [Medium billing risk]**
`infra/terraform/variables.tf:37-41` defaults `budget_notification_email = ""`, and `infra/terraform/main.tf:169-203` makes all three notification blocks `for_each` empty when the email is blank. Result: `terraform apply` with defaults creates a `$300` budget that **never alerts anyone**. For a volunteer/pilot cost guardrail this silently defeats the purpose. Consider making the email required (or `validation`) when the budget is enabled, or documenting it prominently.

**F3 — Per-object S3 tags will not produce per-customer AWS cost attribution. [Medium tagging correctness]**
`storage.py:110` writes `Tagging=urlencode(cost_allocation_tags)` (CustomerAccount/Aircraft/Upload/BillingStage) on each object, and the README (`backend/README.md`) frames these as "billing/cost tags." AWS **cost allocation tags operate at the resource (bucket) level, not per S3 object** — object tags do not surface in Cost Explorer, and Textract API cost cannot be tagged per call at all. Only the bucket-level `Project` tag drives the budget filter (`main.tf:162-167`). If the intent is per-customer AWS billing granularity, object tags won't deliver it; if the real metering is the DB `billable_page_count`/`cost_allocation_tags` on `OCRRun` (which it appears to be), that's fine but the README wording is misleading. Worth clarifying so no one relies on Cost Explorer for per-aircraft breakdown.

**F4 — Deploy IAM policy is broader than "least privilege" in a few spots. [Medium]**
`infra/aws-iam/paprnav-terraform-deploy-policy.json`:
- Line 223: `iam:PassRole` is granted in the management statement scoped to `paprnav-*` roles but **without an `iam:PassedToService` condition**, duplicating/overriding the correctly-scoped statement at lines 247-260. The unconditional one makes the service restriction moot.
- `secretsmanager:*` (line 120) and `budgets:*` (line 78) are wildcards; secrets is at least resource-scoped, budgets is `Resource: "*"`.
- `RegionalDeploymentAccess` grants `ec2:*`, `ecs:*`, `rds:*`, `ecr:*`, `logs:*`, `cloudwatch:*` (lines 55-72), region-gated but service-wildcarded.

For a pilot this may be acceptable, but the PassRole gap in particular undercuts the stated least-privilege goal.

**F5 — mdbtools table names from untrusted ZIP passed as positional CLI args. [Low]**
`drs_bulk_import.py:export_access_table` runs `[MDB_EXPORT, str(accdb_path), table_name]` with `table_name` derived from `mdb-tables` output on an attacker-influenced `.accdb` inside an uploaded ZIP. No shell is used (good, no shell injection), and the accdb is extracted with `Path(member).name` to avoid path traversal (`drs_bulk_import.py`, good). But a table name beginning with `-` could be interpreted as an option by `mdb-export` (argument injection). Low severity/DRS-admin-only, but consider a `--` separator or validating table names. Also note the runtime dependency on `mdb-tables`/`mdb-export` being installed in the container — verify it's added to the image (code falls back gracefully if absent, `parse_access_members_with_mdbtools`).

### Speculative / lower-severity

**F6 — Behavioral change: logbook entry ordering flipped to ascending (oldest-first).**
`logbook_entries.py:88-92` changes ordering from `entry_date.desc()` to `entry_date.asc(), page_order.asc(), created_at.asc()` and adds a `group_by(LogbookEntry.id)` with outer joins to dedupe evidence rows. The dedupe looks correct, but confirm the frontend/UX expects oldest-first now (previously newest-first).

**F7 — Nullable columns typed as non-optional `Mapped[str]`.**
`models/core.py:56,97,201,202` (`customer_account_tag`, `cost_allocation_tag`, `initial_ocr_billable_to_tag`) and `291-295` declare `Mapped[str]`/`Mapped[int]`/`Mapped[dict]` with `nullable=True`. Cosmetic typing inconsistency (matches existing repo pattern); no runtime effect.

**F8 — Missing test coverage for new risk areas.**
- No test asserting Textract/large-PDF behavior or guard (`test_ocr_provider.py` only tests block mapping + provider selection).
- No test for the OpenAI `Responses` HTTP provider path (`OpenAIResponsesADExtractionProvider.extract`) — the LLM path is only exercised via injected fakes.
- No test for unique-tag collision on `customer_account_tag`/`cost_allocation_tag`.

## 4. Brief Summary

Solid, well-tested increment: S3 storage with SSE + cost tags, Textract provider, OpenAI AD-extraction with deterministic fallback, mdbtools DRS parsing, consent-gated uploads, and a reasonably scoped Terraform/IAM pilot. Highest-impact items: (F1) the synchronous Textract path can't handle the multi-page/large PDFs that are the product's core input — guard or go async before enabling; (F2) the default budget has no alert recipients; (F3) per-object S3 tags won't yield per-customer AWS cost attribution — align docs/expectations. IAM PassRole scoping (F4) and mdbtools arg handling (F5) are secondary. Local/CI defaults remain safe.
